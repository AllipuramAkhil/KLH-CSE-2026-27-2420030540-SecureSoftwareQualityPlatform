# ASSQP ML Risk Prediction Service

A standalone FastAPI microservice that predicts software component risk
(`LOW` / `MEDIUM` / `HIGH` / `CRITICAL`) using a `RandomForestClassifier`,
consumed by the ASSQP Spring Boot backend as one input to its **hybrid**
risk assessment (ML prediction + the existing rule-based engine — see
Phase 8 in the root README). This service is entirely optional: if it's
down or unreachable, the backend falls back to the rule-based engine
alone with no loss of core functionality.

## ⚠️ About the training data

**The bundled `data/dataset.csv` is SYNTHETIC / SAMPLE DATA FOR
DEVELOPMENT**, generated by `training/generate_synthetic_dataset.py`. It
does not come from real projects. It exists so this pipeline is runnable
and testable end-to-end before a real historical dataset is available.

The synthetic labels are produced by a simple, documented linear
heuristic (see the script) with noise added — this is *not* a claim
about how real-world risk actually works, just enough signal for a
classifier to learn something plausible for development/demo purposes.
Interestingly, on this synthetic set `LogisticRegression` slightly
outperforms `RandomForestClassifier` (see `--compare-logreg` output) —
expected, since a linear labeling heuristic favors a linear model. Real
historical data, with genuine nonlinear feature interactions, is where
RandomForest is expected to earn its keep; the classifier choice per
this project's requirements is RandomForest regardless.

**To replace it with real data:** once ASSQP has accumulated enough
`AnalysisHistory` / `SecurityVulnerability` / `QualityAnalysis` /
`CiCdPipeline` rows (Phase 9's code-churn data helps here too), export
them into the same `data/dataset.csv` schema (see **Feature reference**
below) with a real `risk_level` label per row, then run:

```bash
python training/train.py --dataset data/dataset.csv --compare-logreg
```

No code changes are needed elsewhere — `train.py`, `model_service.py`,
and the Spring Boot `MlPredictionClient` all key off the same fixed
10-feature contract.

## Feature reference

| Feature | Type | Meaning |
|---|---|---|
| `code_complexity` | float | Cyclomatic complexity (from QualityAnalysis) |
| `code_churn` | float | Git churn score for the component (Phase 9) |
| `historical_defects` | float | Count of past defects/failures |
| `vulnerability_count` | float | Number of security findings on the component |
| `max_vulnerability_severity` | float 0-10 | Highest severity found, numeric scale |
| `test_coverage` | float 0-100 | Test coverage percent |
| `code_smells` | float | Code smell count |
| `duplication` | float 0-100 | Duplicated lines percent |
| `historical_failure_rate` | float 0-1 | Historical test failure rate |
| `technical_debt` | float | Technical debt, hours |

## Running locally

```bash
cd ml-service
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# First time only - generates the synthetic dataset and trains a model:
python training/generate_synthetic_dataset.py
python training/train.py --compare-logreg

uvicorn app.main:app --reload --port 8000
```

Then visit `http://localhost:8000/docs` for interactive OpenAPI docs.

## Running via Docker Compose

From the project root:

```bash
docker compose up ml-service
```

The image trains a model at build time automatically if none exists yet
(see `Dockerfile`). Set `ML_SERVICE_URL=http://ml-service:8000` in the
backend's environment (already wired in `docker-compose.yml`) to enable
hybrid risk assessment.

## API

| Method | Path | Purpose |
|---|---|---|
| GET | `/health` | Liveness + whether a model is currently loaded |
| POST | `/predict-risk` | Predict risk level for one feature set |
| GET | `/model-info` | Model version, algorithm, training metadata |
| GET | `/metrics` | Accuracy / precision / recall / F1 of the current model |
| POST | `/retrain?compare_logreg=true` | Re-run training against the current dataset and hot-reload |
| GET | `/prediction-history?limit=50` | Recent predictions (best-effort JSONL log) |

### `POST /predict-risk` example

Request:
```json
{
  "codeComplexity": 15, "codeChurn": 8, "historicalDefects": 4,
  "vulnerabilityCount": 3, "maxVulnerabilitySeverity": 8, "testCoverage": 65,
  "codeSmells": 12, "duplication": 10, "historicalFailureRate": 0.25,
  "technicalDebt": 5
}
```

Response:
```json
{
  "riskLevel": "LOW",
  "confidence": 0.89,
  "modelVersion": "1.0.0",
  "featureContributions": { "code_complexity": 0.12, "test_coverage": 0.18, "...": "..." }
}
```

`featureContributions` are the trained RandomForest's **global** feature
importances (not per-instance SHAP/LIME — no such dependency is used
here, matching this project's "don't overengineer" MLOps scope). They
indicate which features the model relies on most overall, not why this
specific prediction was made.

## Retraining / versioning notes (Phase 10 MLOps)

Every training run writes `models/model_metadata.json` with: model
version, algorithm, ISO timestamp, dataset path + SHA-256 hash, row
count, feature list, and evaluation metrics. `POST /retrain` re-runs
`training/train.py` as a subprocess against the currently configured
dataset and hot-reloads the result — deliberately simple, no MLflow/job
queue, appropriate for this project's scale. `models/` and `data/` are
mounted as Docker volumes so a container restart doesn't lose a trained
model.
